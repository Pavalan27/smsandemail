Practical Safety Recommendations

Model Scope & Security Advisory

Important Distinction: PhishShift clearly delineates between the statistical Machine Learning prediction, rule-based heuristic indicators, and the composite heuristic risk score.

⚠️ Legitimate does not mean Safe: A message classified as "Legitimate" reflects statistical SMS language similarity only. Sophisticated spear-phishing or newly registered threat domains may evade language models. Always independently verify unexpected requests.

Dataset boundary: The underlying Logistic Regression model was trained on an SMS text dataset. It is not trained or validated for email headers, file attachments, or binary malware payloads.

Three-Tier Architecture

How PhishShift Analyzes Messages

Every submission passes through a privacy-preserving pipeline combining statistical AI with rule-based cyber forensics.

01

In-Memory Input Preprocessing

The user pastes a message into the scanner. Input is sanitized, validated for length limits, and processed strictly in volatile memory. No text is logged to disk or saved to a database.

02

ML & Heuristic Dual Analysis

Sublinear TF-IDF vectorization evaluates word and bi-gram frequencies against a pre-trained Logistic Regression model. Simultaneously, static forensic rules inspect URL domains, IP addresses, and urgency keywords without visiting external links.

03

Actionable Risk Intelligence

The application synthesizes model probability, heuristic indicators, and URL flags into an intuitive 0-100 risk score with tailored defensive steps to protect users from social engineering.

💡 Note on Probabilistic Systems: Machine learning predictions can occasionally be inaccurate. Always use PhishShift as an advisory decision support tool rather than an infallible security oracle.
Engineering & Science

Technical Architecture & Stack

Built with Python Flask, Scikit-Learn, and lightweight vanilla frontend technologies.

🧠

Machine Learning Model

  • Pipeline: TfidfVectorizer + LogisticRegression
  • Vectorization: N-gram range (1, 2), sublinear term frequency, unicode accents stripped
  • Optimization: L2 penalty, balanced class weighting, max 30,000 features
  • Performance: ~96.66% held-out test accuracy on SMS corpus
  • Inference: Loaded once into memory via joblib
🔗

Modular URL Forensics

  • Static Text Analysis: Inspects host, scheme, and path without network calls
  • Host Verification: Flags direct numeric IP addresses and port manipulation
  • Abuse Detection: Identifies high-risk TLDs and known URL shortening services
  • Brand Spoofing: Detects unauthorized brand names embedded in subdomains
  • Extensible: Pluggable architecture ready for VirusTotal / Safe Browsing APIs
🛡️

Privacy & Hardened Security

  • Zero Retention: Message contents are strictly ephemeral and never persisted
  • Sanitized Logging: Server logs capture character count and status code only
  • Input Defense: 10KB message cap, strict JSON validation, client rate limiting
  • XSS Immunity: Dynamic DOM rendering uses pure textContent, never raw HTML
  • Headers: Enforced CSP, nosniff, DENY frame options, referrer policy

Security & Privacy Commitments

How PhishShift safeguards your data and enforces responsible analysis.

1. Ephemeral In-Memory Processing

Submitted text messages are passed directly into the active ML model and discarded immediately after response synthesis. We do not maintain any message database, search index, or persistent cache.

2. Zero Network Fetching for URLs

To eliminate attacker reconnaissance or "canary token" triggers, PhishShift strictly analyzes URL text structure heuristically. It never issues HTTP requests or opens remote websites.

3. Transparent Threat Limitations

No machine learning model is 100% foolproof. PhishShift's model is specialized for SMS patterns and should not be used as the sole defense against complex targeted attacks or email attachments.
